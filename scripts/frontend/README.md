# Front-end differential tools

The engine has two front ends in one binary: the stack-code one and the new
one (AST, HIR, MIR). `qjs --frontend=old|new`, the `OXIDE_FRONTEND` variable,
or a build's `OXIDE_DEFAULT_FRONTEND` selects one. These tools compare them.

| Tool | Compares |
| --- | --- |
| `diff.py PATH...` | stdout, stderr and exit status of `qjs --frontend=old` and `--frontend=new` for each `.js` file; a first line `// qjs: ARGS` passes arguments |
| `test262.sh old\|new REPORT [ARGS...]` | runs Test262 with one front end (a development run with a fixed fingerprint, not the gate) |
| `compare-test262.py OLD NEW` | two Test262 reports variant by variant: what passes in OLD and fails in NEW, grouped by failure |

The inputs that must agree: `core/tests/corpus`, `docs/performance/probes`,
the suite programs (`target/suite-matrix`) and the position cases in
`tests/frontend/positions` (generated by its `generate.py`), which throw from
each construct and print the stack.

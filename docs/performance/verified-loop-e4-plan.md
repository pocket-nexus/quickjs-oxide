# E4：拆小热循环与发布时预解码

状态：设计及基线核对完成，尚未实现 E4 运行时候选。
E3 保留在实验分支，作为 E4 的实现基础；其单独性能门槛仍未通过。
本计划不宣布 E3 已采纳，也不恢复整个 B/C 迁移。

## 依据与归因范围

E3 数值循环为 874 Ir/迭代、12 次实际分派、72.83 Ir/分派、
136 Dw/迭代（11.33 Dw/分派）。原来 ≤40 Ir/分派、400–500 Ir/迭代的目标保留。

地址账本指出两类值得进行结构实验的工作：

- 共享字流读取、cursor/next-PC、解码和 tag 选择区间合计 340 Ir/迭代，即约 28.33/分派。
  它包括格式解析、状态搬运、边界保护和跳转表处理，不能全部归给可变宽度格式。
  当前 next_pc 实际使用已编码的 width 位；count/first_wide 还用于操作数访问。
- 使用栈内存/地址的指令合计 213 Ir/迭代。它包括热状态和临时结果的读写，
  不能将全部 213 都认定为寄存器 spill，也不能与共享区间再次相加。

本机普通 Rust 1.88 release 的链接后汇编：

| 指标 | E2 `afadba63` | E3 `f0e98a3b` |
| --- | ---: | ---: |
| 主解释函数字节数 | 63,888 | 64,924 |
| 静态机器指令数 | 13,195 | 13,067 |
| prologue 显式栈空间预留 | 1784 B | 2008 B |
| 使用 rsp 的静态内存/地址指令 | 2930 | 3177 |
| 不同的固定 rsp 位移 | 251 | 296 |

这些是当前构建的具体值。显式预留不包含全部 saved-register/返回地址空间；
不同位移不等于逻辑变量或 LLVM spill slot 数。
巨大函数、较多活跃状态和取地址的聚合体是待验证的机制，函数拆分及 inline 属性本身不保证改善。

### 已补采硬件计数

相同冻结 DeltaBlue/Crypto 工作量，E2/E3 各一次，CPU 4，普通 release，无 PGO。
perf 采 userspace 整进程 counters；没有并行构建、测试或 Callgrind，未修改 governor。
所有 events 的 running 为 100%，工作量、二进制 SHA、stdout/exit/stderr 均验证。

| 负载 | instructions | cycles | L1d load misses | CPI | frontend_bound |
| --- | ---: | ---: | ---: | ---: | --- |
| DeltaBlue | −1.00% | +8.61% | +12.79% | +9.70% | 16.5% → 18.9% |
| Crypto | −9.75% | +11.48% | +15.01% | +23.52% | 17.9% → 17.2% |

单次结果支持“指令减少，但每指令成本和数据缺失增加”的判断，与 E3 原生短测方向一致。
它不能证明增加的全部 miss 来自 spill，也不能将 miss 数换算成损失的 cycles。
Crypto 的 frontend_bound 比例没有上升；不能把两项都归结为取指瓶颈。
frontend_bound 是 AMD 的未供给 dispatch-slot 比例，不是 L1i miss 数。

原始 perf CSV、汇编、SHA 和采样回执见
[verified-loop-e4-evidence.json](verified-loop-e4-evidence.json)。

## 保留的合同与允许的交换

- 规范操作数 Vec，活跃前缀拥有引用，非活跃后缀没有引用 owner。
- 一个执行片段借用当前帧切片；正确发布深度、fault/resume PC。
- State 直接清理、guard/error/panic 合同，回调前结束短期借用；保持现有 poison 行为。
- 普通调用/返回继续在内部执行循环推进；保持 TDZ、capture、getter/Proxy、构造和挂起语义。
- safe Rust，保留边界保护和外部验证；此次不削弱 heap 句柄认证。
- 放宽“不新增每字节码元数据”的限制，以执行时间、Ir/Dw、代码和运行期内存交换评价。
  增加元数据不是验收结果，必须计入发布时间、分配失败、字节数和峰值内存。

E3 是一种已验证的实现基础，不是表示路线的理论最优值。
E4 也不预先承诺 ≤40 或 R/D 的整体收益。

## 分提交实验

### E4.0：固定证据（已完成）

保存 E2/E3 二进制及原回执，复用 E3 的冻结 Ir/Dr/Dw、探针和 opcode 诊断。
补采本页的硬件/汇编基线；不重新校准工作量，不增加计时轮数。

### E4.1：只拆执行结构，保留当前字流

核心循环保留频繁的操作族：常量、局部/参数读写、数值算术、比较/分支、Goto、
普通字段/数组直接消费、普通调用/返回。具体名单按全八项已有 profile 和实际可达代码确定，
不能机械地把“二三十条”当作配额，也不能移走 NS 频繁使用的融合数值消费者。

把低频语义主体及大型失败分支抽到直接接收借用资源的函数，使用 `#[inline(never)]`；
`#[cold]` 只用于已证实低频的分支。已有 deferred_action 已经分离，
重点是仍膨胀主函数的大型主体和控制，而不是重新包装这些已有边界。

实现要求：

- 热成功路径不构造通用 operand/progress/Query，不组装或复制整个执行上下文。
- pc、depth、切片地址等通过当前片段的局部状态推进；冷 helper 交接只在选中冷路径之后发生。
- 冷 helper 短期借用 State、规范槽位及必要字段，直接消费；真实 JS 等待复用现有边界。
  控制返回必须实际紧凑，避免将整个 decoder 或大型聚合体来回传递。
- 冷 helper 修改深度、报错、返回边界后，现有 guard 仍能看到最新的 owner 前缀及 fault PC。
  不建立第二份 owning 栈，不依赖正常返回后的手动同步兜底。
- 热数值 helper 的调用及返回临时值也接受汇编检查；拆分不能引入每次算术的全状态保存/恢复。

这个提交独立测量：函数/栈空间、热地址上的实际栈读写，以及探针和 R/D/NS/Crypto Ir/Dw。
只改源码函数长度或 inline 属性不能算机制达成；不要求这个单独提交同时兑现格式优化的收益。

### E4.2：独立试发布时预解码

首选预解码，以限制控制流协议迁移。保留紧凑字流作为验证/恢复的权威表示，
现有 word PC、fault/resume、target、numeric region 和 freeze/thaw 的单位不变。

发布阶段在已有验证之后生成直接按 word PC 索引的执行表：

- 起始位置保存 opcode、已恢复的操作数与 next_pc；扩展字位置不作为合法入口。
- 热访问一次安全索引后借用 entry，按消费者读取字段；禁止 `Cell<整个 entry>::get()` 搬运整条记录。
- PushI32 等短/宽操作数的语义在发布时恢复，避免热消费者再次按 width 判定。
- 多操作数路径也直接使用已发布事实；不在频繁的融合 opcode 上重新解析旧 header。
- 无 hot PC → source PC → hot PC 的逐次查找或二分搜索，不在每次分派里重建摘要。

按 word 索引的表可能给扩展字位置留下空间，必须记录这项真实开销。
entry 布局根据操作数覆盖与大小审查确定；不默认较大的扁平结构一定比紧凑字流更好。
记录 bytes/word、bytes/instruction、总执行表字节、发布时间和 RSS。

一致性要求：

- 先完整生成并验证，成功后发布；失败不能留下半张表或已发布的半成品。
- opcode 是唯一需要可变的部分时，仅该字段使用 Cell。新增表不是第二个可独立修改的权威。
- 当前 `quicken_same_width` 只在 cfg(test) 下存在。若保留/扩展 quickening，
  必须让唯一修改入口保持字流/执行表一致、验证失败能回滚，并测试恢复和所有合法配对。
  不能只因为使用 Cell 就宣布一致性成立。
- 验证所有 target/next_pc 对应合法边界，恢复后沿用正确执行表；外部及 synthetic admission 仍验证。

预解码的内存/发布成本或查找形态不合格时，撤回这个候选，固定宽度 u64 作为另一项独立实验。
两种格式和热循环拆分不绑定到同一个提交；不同时保留两套生产执行路径。

### E4.3：组合验收与复盘

每步先与前一验证版本比较，再将组合直接对 E3 和已采纳 B2a 的匹配普通 release。
E3 本身未获得整体收益，优于 E3 还不能替代对已采纳版本的累计验收。

最终机制目标：

| 指标 | 目标/要求 |
| --- | --- |
| 数值探针 Ir/实际分派 | ≤40 |
| 数值探针 Dw/实际分派 | 2–3，使用实际分派数归一化 |
| 数值探针 Ir/JS 迭代 | 400–500；保留 N/2N/4N 线性与输出验证 |
| 核心函数栈及热状态访问 | 汇编确认预留空间和热 spill/reload 明显下降；固定 rsp 位移仅作代理指标 |
| R/D/NS Ir 和 Dw | 同时下降后进入原生短测 |
| Crypto | 跟踪此次已出现的 Dw/L1d/cycles 代价，不能由其他负载抵消 |
| 峰值 RSS/代码大小 | 沿用 +5%/+10% 预算，执行表数据开销与发布成本另列 |

复用 archived baseline profile。日常原生仍为一个 ABBA 块，各侧两次，
八项及 Combined；计时期间不并行编译、测试、Callgrind。
在确有需要的对照点才再采硬件计数，不把一次硬件结果或两次时间样本宣布为正式验收。
I1mr 继续只作诊断，不调布局，不把指令下降自动换算成 Score。

每个运行时提交保持可编译并跑受影响的正确性检查；组合结束覆盖现有库测试、
profiling 检查、focused Test262，以及代码发布、边界映射、异常、调用/返回、
getter/Proxy 和挂起恢复。正式采纳时按原阶段合同补齐完整验收。

在 E4.3 停下来复盘：采纳有净价值的组合、缩小实验或撤回候选。
最终全八项和 Combined 超过历史 Boa 的目标及 B 的架构合同保留；
E4 不以机制目标的通过宣称这些大目标完成。

# 2026-09-25 实施门禁：#41 与数值数组 R0

> 这是先前 R0／#41 独立候选测量的**文字摘要**和当时的门禁裁决，不是当前完整集成分支的状态。后续已按用户要求实现并发布全部 13 种跨度并合入 #41；组合版实测另见[四方总结](../fourway-2026-09-25/README.md)。原始样本保留在本机测量目录，不进入 PR。

本轮按 [实施设计](../../implementation.md) 分模块完成了 #41 错误载体候选、R0 发布器、存储原语和执行接线。正式性能运行在同一台 AMD Ryzen 7 7840HS、Rust 1.94.1、普通 fat-LTO/CGU=1 release 上串行进行。**两个候选都未接纳；R1–R4、A0–A3、W0–W3 没有发布。** 当前可接纳基线仍为 `2ed79f46`（引擎源码与文档规定的 R0 `f531f605` 相同）。

实验源码身份是 R0 候选 `7b4cc915` 和 #41 候选 `04bb1a74`。当时的结果分支只保存了证据与拒绝决定，随后用户要求完成全部产品代码。微负载采用两轮、每轮每边五个进程的 ABBA/BAAB 顺序，先在同一二进制上做 A/A；本 PR 只保留下面的结果总结，不提交逐次样本和负载文件。

## 数值数组 R0：真实覆盖，但净收益未过门

发布后 dump 与生产 matcher 的完整 [PC 清单](../r0-d6080b38/README.md)确认四个目标函数各一份。23 个 `GetArrayEl` 站点中仅 R0 发布 6 个：am3 两个、lin_solve 三个、advect 一个、project 零个；其余 17 个分别因 base 非 direct（13）或 key 非单个数值 source（4）被拒绝。profiling 构建在完整 Crypto 负载上记录 `fusion.DenseRead=15,562,241`，因此 Crypto 回退不是零动态命中造成的。

| 固定负载 | 首版 `a904aef2` 指令变化 | 内联查询版 `7b4cc915` 指令变化 |
| --- | ---: | ---: |
| `dense_r0_read`（R0 命中，10M 轮） | −16.68% | −17.81% |
| `array_read`（数值下标表达式，R0 不命中） | +2.70% | +1.03% |
| `empty_loop` | +0.29% | 约 0% |
| `int_local` | +0.22% | 约 0% |
| `prop_read` | +0.13% | −0.13% |

首版 release 反汇编中，`FusionPlan::dense_span` 是独立 36B 函数，并在 `run` 的 local/arg 臂调用；内联版消除了该符号和多数非命中入口税。两版 `run` 栈帧均为 `0xea8`。这个调整使固定 `array_read` 回到 +2% 指令门内，却没有解决真实 Crypto。

首版完整八项 V8 隔离测量各有五个有效进程，Crypto Score 中位数 `71.3→68.3`（−4.21%），NavierStokes `271→291`（+7.38%）；八项中位数几何比为约 `0.998`。内联版定向复测 Crypto、NavierStokes、Richards 各五次：Crypto `71.2→68.4`（−3.93%，两组范围分别 `70.7–71.8` 与 `67.5–68.9`），NavierStokes `271→272`（+0.37%），Richards `55.8→55.8`。首版正收益不能替内联版背书；内联版因 Crypto 稳定超过 −2% 硬门而未再运行剩余五项或 combined。R0 命中微负载也未达到继续扩大 P2 的 −30% 指令门槛。

**当时的裁决：** 拒绝 R0 并停止后续切片；这不是当前分支的代码状态。后来按照用户要求完成并发布全部 13 种跨度，四方正式结果见[新总结](../fourway-2026-09-25/README.md)。旧负结果继续保留，不能用新结果抹掉。

R0 代码验证：workspace/all-targets 测试、Rust 1.88.0 clippy `-D warnings`、格式、源码布局、Test262 focused `6844/6844` 均通过；完整 Test262 冻结结果向量匹配（总计 102037 变体，80010 个预期通过、3552 个既有失败、3502 个 unsupported、18475 个 skipped）。这些正确性结果不抵消性能拒绝。

## #41：指令改善，但 cycles 与错误分配未过门

原 `0cd4acee` 的 8B `Error(Box<ErrorData>)` 候选已恢复并补公共语义测试。Rust 1.88.0 定向 22 项测试、clippy 与格式通过。13 个历史固定负载逐项确认基线/候选 stdout、stderr 和退出码一致；候选退休指令全部下降，例如 `array_read` −4.59%、`prop_write` −4.53%、`call0` −6.16%、`bigint32` −9.13%。

| cycles 负载 | A/A 第 1 / 2 轮 | 基线/候选第 1 / 2 轮 | 全部样本中位数变化 |
| --- | ---: | ---: | ---: |
| `prop_write` | −1.06% / +0.16% | +11.04% / +10.95% | +10.87% |
| `string_build1` | −0.35% / −1.15% | +4.42% / +3.94% | +4.09% |

错误分配探针分别链接干净 R0 与 #41 候选，四种模式每边各十个独立进程、固定 100,000 次操作；其带计数器的耗时只用于诊断，不作为正式 Score。`success` 两边均零分配。`construct` 与 `propagate` 每 100,000 次的分配分别从 `100,000 / 1.3MB` 升至 `200,000 / 9.3MB`，即每个错误多一次 80B Box 分配。`retain` 的峰值 live bytes 同样为 `1.3→9.3MB`，Linux RSS HWM 中位数为 `13,312→15,652 KiB`（+2,340 KiB，约 +17.6%）。这些数字来自诊断二进制，并不冒充 CLI 的正式 Score 或全引擎 RSS。

**裁决：** #41 不接纳。`prop_write` 的稳定 cycles 回退和错误负载的分配/RSS 增加均越过 [统一门禁](../../measurement.md)；因此无需为这个已失败的候选继续跑完整 V8 或 Test262 full。数组实验始终以原 R0 为基线，未借用 #41 的历史正面指令报告。若将来修改错误载体策略，应以新身份重新从零测量。

当时未运行 R0 内联版的完整八项和 combined、#41 的完整 V8/Test262，也未给出 Candidate/B37 总分；这些项目没有被标作通过。后续完整组合版的测量须按自己的[四方总结](../fourway-2026-09-25/README.md)阅读，不能挪用此处独立候选的门禁结论。

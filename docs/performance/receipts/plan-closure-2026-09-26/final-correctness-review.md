# Final candidate `8d3875dc` static correctness review

Read-only source review against `8525105d` (`git diff 8525105d 8d3875dc`). No VM execution, build, or tests were run for this review. The finding is limited to the changed paths and cited invariants; it is not a proof that all JavaScript programs are correct.

## Receiver copy and ordinary frame installation

No blocking ownership or exception-order defect found in the final receiver rollback. The ordinary operand witness checks receiver, arguments left-to-right, then callee before authentication (`src/engine/vm/stack/window.rs:78–119`; `src/engine/vm/driver/ordinary.rs:129–150`). Installation then reserves call depth and validates resume PC before copying the method receiver (`src/engine/vm/call/ordinary.rs:307–322`), preserving the pre-transfer error order. `copy_value` duplicates the receiver's reference edge on success (`src/engine/vm/stack.rs:1716–1766`). The result is **immediately** put in `CallInput` before `capture_flags`, `prepare_push`, `current_mut`, and `push_ordinary_frame`, all of which can return an error (`src/engine/vm/call/ordinary.rs:323–355`). `CallInput::Drop` releases the edge on any such return (`src/engine/vm/protocol.rs:49–81`); on success it moves into `cold.input` (`ordinary.rs:357–371`) without a second copy or release.

`push_ordinary_frame` checks window identity, depth, capacity and reservations before changing caller operands (`src/engine/vm/stack/call.rs:15–61`). It retains staged non-scalar arguments in the unpublished suffix and rolls them back on failure (`call.rs:68–86`). It then moves arguments, releases the caller's original receiver and callee, and updates window/depth (`call.rs:110–123`). The release API is nothrow for all current `FrameBinding` variants (`src/engine/vm/bindings.rs:46–70`, `src/engine/value/js_value.rs:461–485`), so the `?` in the post-move release loop cannot currently leave a partially published child via a returned error. That property is an implementation dependency: future changes to release semantics would require revisiting this transaction boundary.

The copied receiver remains a distinct counted edge while the caller operand is released. The focused source tests check strong counts of 2 before install, 1 after caller release, GC survival until `CallInput` drop, and guard cleanup after an argument-copy failure (`src/engine/vm/stack/call.rs:330–493`). Higher-level tests cover a nested method call with a caught throw and native/general fallback (`src/engine/vm/call/ordinary.rs:440–466`). This review inspected the tests but did not execute them.

## Named local failure rollback

The independent repair remains present. If `initial_local_binding` fails, it releases the staged parameter copies and all preceding local bindings from `original_end..parameters_end + index`, then returns the original converted error (`src/engine/vm/stack/call.rs:92–109`). The first owner move from caller slots occurs only afterward (`call.rs:110–117`); `active_end`, `parent.depth` and `next_window` also change only after the release boundary (`call.rs:118–123`). Thus an initialization error leaves the parent operands in place and the unpublished suffix empty. `clear_unpublished` takes each staged binding before releasing it (`src/engine/vm/stack.rs:745–754`); the ignored rollback result cannot currently mask a release error because `release_binding` is nothrow. The focused stale-function test inspects the unchanged receiver/argument slots, strong counts, suffix and depth (`src/engine/vm/stack/call.rs:495–594`). Again, it was not rerun here.

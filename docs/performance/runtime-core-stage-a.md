## 已采纳机制

| 提交或提交组 | 实际变化 |
| --- | --- |

GNU size 的 text（含只读数据）从 **8,288,860 → 8,586,924 bytes，增加 3.60%**，低于 10% 上限。

丢弃自引用节点与闭包环分别运行 65,536、262,144、1,048,576 次，两对每规模。工作量增大 16 倍后，基线与阶段 A 的最大规模峰值均满足最小规模加 max(1 MiB, 5%) 的有界观察条件，两个最大规模的末段窗口也稳定。阶段 A 的节点环峰值为 14,112 → 14,372 KiB，闭包环为 14,224 → 14,396 KiB。

完整原始结果还保留一个资源差异：中间规模闭包环的阶段 A 峰值为 15,344 KiB，基线为 14,384 KiB，增加 **960 KiB（6.67%）**。collector 额外对合成持续负载套用了固定 benchmark 的 5% 比较，因这一项返回 false；批准的固定 RSS 与持续分配有界门槛分别验收，不能把这条额外诊断删掉或标成通过。

最初 50ms RSS 采样只拿到最小节点环的两个点，未达到窗口统计要求；不完整回执保留，仅持续分配部分改为 10ms 采样。固定 RSS、代码体积与成绩没有重跑。这里的采样有界证据不是对所有程序的数学内存上界证明。

GC 仍有同步停顿。最终诊断构建的 DeltaBlue 记录一次约 **2.32ms** inclusive 自动 GC；Richards 没有相应样本，不代表零停顿。这些诊断时钟不能作为 plain 构建的最大停顿或分布。最终 release 构建耗时 105.04s、峰值 1,988,060 KiB；没有同口径基线构建耗时，因此不宣称编译收益。

## 机制与正确性

机制计数独立于 plain 计时：

| 固定负载事件 | Richards：基线 → 阶段 A | DeltaBlue：基线 → 阶段 A |
| --- | ---: | ---: |
| call 退出到 ready | 849,792 → 2 | 1,500,732 → 56,955 |
| return 退出到 ready | 850,234 → 3 | 1,473,212 → 10,574 |
| 核心范围 Runtime Rc clone | 3,019,119 → 1,315,081 | 4,565,671 → 1,400,731 |
| PC 重新认证 | 2,281,475 → 524,690 | 3,309,226 → 383,947 |
| 窗口重新认证 | 3,201,032 → 594,457 | 5,038,458 → 669,402 |

内部完成数加剩余退出数与原调用/返回总数逐项一致。Runtime clone 的范围是 profiling 标记的核心执行，不能推广为全局 Rc 次数。剩余百万级状态借用及 legacy 属性、native 边界是阶段 B 的实际迁移目标；诊断 phase 抽样有覆盖与截断限制，不出现某个 phase 不能说明其成本为零。

- 原生 CI 44/44 命令通过，含严格 Clippy、doctest、native CLI 和 wasm32。默认 parent harness 3,260 pass/1 existing ignore，组合 features 3,496 pass/1 ignore；不把 feature 重复与嵌套 poison 子进程相加为独立测试。
- focused Test262 6,844/6,844；完整 80,010/80,060 runnable、102,037 total，冻结 TSV/JSONL 的所有分类及既有 50 个失败完全一致。
- 固定 QuickJS 私有不可变参考：38 个 CLI 与 913 个 oracle 通过，1 个既有 ignore；13 个 JS 与 9 个 C fixture 通过。共享参考二进制发生改写的早期运行未进入验收。
